              From signed file to explained decision

              The same six steps run for every document, so a reviewer can see what was checked and why.

              1. UploadA PDF or supported document with a digital signature.
              2. VerifyCheck the SHA-256 hash, signature validity, and available certificate details.
              3. AnalyzeIsolation Forest and XGBoost study signing behavior. QUBO keeps the most useful features.
              4. OptimizeQUBO with simulated annealing keeps only the features worth using.
              5. ScoreA 0 to 100 risk score, with SHAP explaining which issues drove it.
              6. RecordSave the result and optionally anchor its hash on an EVM testnet.

              Four ways a signed file goes wrong

              Checking the signature alone misses most of them.

              Document tampering

              The file was edited after signing. A hash mismatch exposes it.

              Compromised signing key

              A stolen key signs correctly but from the wrong place, device, or time.

              Replay attacks

              An old valid request is sent again to repeat an approval.

              Abnormal signing activity

              Bursts, odd hours, and unknown devices stand out from a signer's usual pattern.

              Open-source tools, no quantum hardware

              QUBO feature selection runs on a classical simulated-annealing solver, so everything runs on ordinary servers.

              Security

              • Python cryptography library for signatures
              • SHA-256 document integrity
              • RSA and ECDSA verification
              • Replay and certificate checks

              AI and optimization

              • Isolation Forest (Scikit-learn) for anomalies
              • XGBoost for classification
              • SHAP for explanations
              • QUBO feature selection with simulated annealing

              App and audit

              • React or plain JavaScript frontend
              • Python and FastAPI backend
              • SQLite database to start
              • Solidity contract on an EVM testnet
